## Priority findings

P2 denotes a normal-priority functional/accessibility bug. Findings concern the reviewed revision; some existed before its latest four commits.

### 1. P2 — Comparison and review action can refer to different photographs

**Locations:** `components/mission-control.tsx:56–59`; `components/evidence-visuals.tsx:45–51`.

The comparison component owns its A/B selection independently of Mission control's `selected` frame. Changing comparison photos does not change the parent selection used by the inspector, evidence flow and “Review this photo” action. For example, select Scenic Reflection, enter Compare and change A to Sambhaji while B remains Mutha: the action still begins a Scenic Reflection review. Comparison's own A/B credits are correct; the parent action/attribution is the mismatch. A saved parent record similarly retains its unrelated replay/receipt.

**Correction:** share the active selection, or offer explicitly named Review A/Review B actions and keep unrelated selected-frame panels out of comparison mode. Verify credits, inspector and review draft all refer to the intended source after switching either photo.

**Evidence:** source tracing; no browser reproduction.

### 2. P3 — Interrupted reference preparation has no recoverable loading state

**Locations:** `components/streamcheck.tsx:201`, `:209`, `:246`, `:347–375`, `:602`, `:637`; `lib/field.ts:144`, `:161`.

Reloading while a reference image is being prepared leaves a saved reference draft without its required credited media. Restoration rejects this incomplete draft and returns to an empty form rather than resuming the selection. A fetch/retention failure similarly resets the selection. Retrying from Mission control is possible, so this is a recovery/experience issue rather than demonstrated citizen-text loss.

**Correction:** retain a pending source identifier and show an explicit retry state without treating it as a completed reference record. Keep the existing edit/analysis guards while preparing the source.

**Evidence:** source tracing and incomplete-reference schema rejection; no browser test. A second pass ruled out the original suspected note-loss trigger: the form and FieldStudio are hidden while `referenceLoading` is set, and the temporary note is empty. Users cannot type the claimed note during loading.

### 3. P2 — Some map, River and Evidence Lab text has insufficient contrast

**Locations:** `app/layout.tsx:5–11`; `app/console.css:120–135`; `app/geographic-map.css:46`, `:53`; `app/evidence-lab.css:95`; `app/river.css:53`, `:69–76`.

The new dark shell overrides panel backgrounds while several child foregrounds retain older dark colors, and some light River cards inherit pale text. Source-derived examples include map headings at approximately 1.72:1, map coordinates at 1.93:1 and a lab response at 2.04:1. These make substantive evidence information difficult to read.

**Correction:** apply paired foreground/background tokens to the actual child selectors. Manually inspect map dossiers, River cards, lab responses, empty/error states and focus indicators on mobile and desktop.

**Evidence:** stylesheet inspection and computed color-pair contrast, not rendered-page observation or an accessibility certification.

### 4. P2 — Photo pins can describe padding rather than image coordinates

**Locations:** `lib/mission-control.ts:19`; `components/photo-inspector.tsx:29–30`; `app/console.css:226–227`.

Stored photo dimensions may be zero. When both are nonpositive, Mission control substitutes a 4:3 frame; one missing dimension can also create an incorrect aspect ratio. The image uses `object-fit: contain`, but pins normalize the entire frame rectangle, including letterbox padding. For a 2:1 image inside the 4:3 fallback, the image's top edge exports `y = 1/6` instead of `0`, and padding can receive a pin. Correct stored aspect ratios avoid this mismatch. The pin can remain visually at its clicked position while its exported coordinate is wrong relative to actual image pixels.

**Correction:** use the loaded image's natural dimensions or its rendered image bounds; reject padding placement and disable placement until dimensions are available. Preserve the original stored metadata.

**Evidence:** source and geometry analysis; no pointer/browser test.

### 5. P2 — A failed field-pack import can leave unused media in storage

**Locations:** `components/collection-tools.tsx:52–53`; `components/streamcheck.tsx:510`.

Import commits absent media to IndexedDB before committing the report collection to localStorage. If report persistence fails, the UI reports failure but newly added media for new records remains without corresponding records. Failed imports involving different new media can accumulate unused storage. Retrying the same pack skips already retained blobs, so it does not repeatedly duplicate those files; files restored for identical existing reports remain useful.

**Correction:** track newly added media IDs and roll them back on report commit failure, or retain a recoverable import journal. Never remove pre-existing media. Exercise quota/error paths for both stores.

**Evidence:** source failure-path tracing; storage failure was not induced in a browser.

### 6. P2 — Rapid video-start actions can bypass the ten-second stop

**Locations:** `components/field-studio.tsx:269–305`.

`record()` checks React state and then awaits poster capture before setting recording state. Two activations during that await can create two recorders. Both use one shared timer reference; when the first stops, it can clear the second recorder's timer, leaving that recorder active beyond the intended limit.

**Correction:** acquire a synchronous start guard before the first await; keep each recorder's timer and stop/cleanup lifecycle consistent. Verify double activation, capture failure, unmount and manual stop.

**Evidence:** isolated execution of the extracted recording function with deferred frame capture, fake recorders and mock timers reproduced two recorders, the second timer being cleared and the second recorder remaining active. Result: `.sites-runtime/review-2026-10-01/capture-race.json`. This does not constitute a real-camera test.
