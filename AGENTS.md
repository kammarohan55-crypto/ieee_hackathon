# Instructions for any AI working in this project

## Start here
- Read `PROJECT_CONTEXT.md` first. Read `docs/BUILD_PLAN.md` only for implementation work and `docs/SOURCES.md` when checking external claims.
- Inspect the actual files and Git state before editing. Documentation describes intent; code and command output establish implementation status.
- The user wants efficient token use, reliable claims, and continuity between AI sessions. Keep updates concise. Do not reread entire histories or duplicate research without a reason.

## Truth and evidence
- Distinguish verified external facts, user statements, project decisions, assumptions, and unverified claims.
- Never invent APIs, data access, environmental thresholds, scientific validation, test results, deployed features, or competition results.
- Record external claims with source URL, date checked, and limitations in `docs/SOURCES.md`.
- Label synthetic observations and recorded AI responses visibly. Human confirmation establishes authorship/approval, not scientific truth.
- Preserve original observations. AI may suggest; the citizen or reviewer must explicitly accept edits. Unknown information stays unknown.
- Do not infer water safety, pathogens, disease risk, pollutant identity, or ecological status from appearance or text alone.
- Keep API keys out of client code, committed files, exported reports, and screenshots.

## Scope and handoff
- Latest user direction permits natural multi-track scope. Retain the citizen-to-reviewer assessment spine; citizen UX (Track 1), contextual insight (Track 2), responsible assessment (Track 3) and storytelling (Track 4) may all contribute. Do not speculate about the easiest track to win or claim entrant-specific multi-track eligibility. Final submission choices need actual user/Devpost confirmation. Working names AquaLens / StreamCheck imply neither uniqueness nor organizer endorsement.
- Complete the narrow citizen-to-reviewer workflow before optional features. Do not add forecasting, custom model training, or FHIR claims without evidence and a scope decision.
- Run meaningful checks appropriate to changes; report failures and untested behavior plainly.
- At the end of each substantial work session, update `PROJECT_CONTEXT.md`: completed work, verification results, decisions, open issues, and exact next step. Replace stale status instead of growing a transcript.
- Never claim another AI automatically remembers this chat. A new AI must receive this workspace or these files.
